## はじめに

MP Ukagaka は WordPress プラグインで、サイトにインタラクティブなデスクトップマスコットキャラクター（伺か）を表示できます。キャラクターはカスタムダイアログメッセージを表示でき、AI インテリジェントページ感知機能をサポートし、記事内容に基づいて自動的にコメントを生成します。

### 主な機能

- 🎨 **複数キャラクターサポート**：複数の伺かキャラクターを作成・管理
- 💬 **カスタムダイアログ**：各キャラクターに専用のダイアログ内容を設定
- 🤖 **汎用 LLM インターフェース**：Ollama、Gemini、OpenAI、Claude の 4 大 AI サービスをサポート
- 🧠 **AI ページ感知**：記事内容に基づいて自動的にコメントを生成
- 🌍 **多言語**：繁体字中国語、日本語、英語をサポート
- 📁 **外部ダイアログファイル**：TXT と JSON 形式のダイアログファイルをサポート
- ⚙️ **高度にカスタマイズ可能**：タイプ速度、表示位置、スタイルなどを調整可能
- 🎭 **カスタムプロンプトシステム**：Markdown 形式の System Prompt をサポート、構造化されたキャラクター設定

## インストールと有効化

### システム要件

- WordPress 5.0 以上
- PHP 7.4 以上
- JavaScript をサポートするモダンブラウザ

### インストール手順

1. プラグイン ZIP ファイルをダウンロード
2. WordPress 管理画面にログイン → **プラグイン** → **新規追加**
3. 「プラグインをアップロード」をクリック、ダウンロードした ZIP ファイルを選択
4. 「今すぐインストール」をクリック
5. インストール完了後、「プラグインを有効化」をクリック

有効化後、**設定** → **MP Ukagaka** で設定を行います。

## 基本設定

**設定** → **MP Ukagaka** → **⚙️ 通用設定** に移動

### 表示設定

| 設定項目 | 説明 |
| --- | --- |
| デフォルト伺か | デフォルトで表示するキャラクターを選択 |
| デフォルトで伺かを表示 | デフォルトでキャラクター画像を表示するかどうか |
| デフォルトで吹き出しを表示 | デフォルトで吹き出しを表示するかどうか |

### ダイアログ設定

| 設定項目 | 説明 |
| --- | --- |
| デフォルト会話 | 「ランダム」または「最初の一つ」 |
| 会話順序 | クリック時の次の会話は「順序」または「ランダム」 |
| 伺かをクリック | キャラクタークリック時の動作（次を表示または何もしない） |

### 自動ダイアログ

| 設定項目 | 説明 |
| --- | --- |
| 自動ダイアログ機能を有効化 | 自動的にダイアログを切り替えるかどうか |
| 自動ダイアログ間隔 | 自動切り替えの間隔（3-30 秒） |
| タイプ効果速度 | ダイアログのタイプアニメーション速度（10-200 ミリ秒/文字） |

### ページ除外

「以下のページで伺かを表示しない」テキストボックスに、伺かを表示したくないページの URL を入力、1 行に 1 つ。

あいまいマッチをサポート：URL の末尾に `(*)` を追加すると、すべてのサブページにマッチ。

```
/admin/
/wp-admin/(*)
/private-page/
```

### スタイル設定

| 設定項目 | 説明 |
| --- | --- |
| カスタムスタイルを使用 | 有効にすると、プラグインは内蔵 CSS を読み込まず、外観を自分で制御可能 |
| カスタムスタイルリンク | `<link>` タグを入力して、独自の CSS スタイルシートを読み込める |

> 💡 このオプションは上級ユーザー向けです。有効にした場合、**テーマの CSS** または「カスタムスタイルリンク」から独自のスタイルシートを読み込む必要があります。CSS をカスタマイズする予定がない場合は、オフのままにして内蔵スタイルを使用してください。

```html
<link rel="stylesheet" href="https://example.com/custom-ukagaka.css" type="text/css" />
```

## 伺か管理

### 既存の伺かを表示

**設定** → **MP Ukagaka** → **👻 偽春菜們** に移動

このページでは、すべての伺かを表示、名前/画像/ダイアログを編集、デフォルト以外の伺かを削除、表示するかどうかを設定できます。

### 新しい伺かをインストール（ZIP アップロード）

MP Ukagaka は ZIP ファイルをアップロードしてキャラクターをインストールまたは更新することをサポートしています。

#### ZIP ファイルの準備

ZIP ファイルのルートディレクトリに直接以下が含まれている必要があります：

- `manifest.json`：キャラクター設定ファイル（必須）
- `shell/`：キャラクター画像フォルダ（必須）
- その他ファイル（`prompts.json`、`decorations.json` など）

> ⚠️ これらのファイルとフォルダが ZIP のルートディレクトリに直接含まれていることを確認してください（別のフォルダの中に入れないでください）。

#### アップロード手順

1. **設定** → **MP Ukagaka** → **👻 偽春菜們** に移動
2. ページ上部の「**ZIP をアップロード**」ボタンをクリック
3. 準備した ZIP ファイルを選択
4. アップロード完了を待つ（システムが自動的に検証してインストール）
5. インストール完了後、新しいキャラクターがリストに表示される

### 新しい伺かを作成

> 📘 **上級ガイド**：完全な LLM サポートを含むキャラクター人格を作成する場合は、[人格作成ガイド](GHOST_CREATE_GUIDE.md) を参照してください。

**設定** → **MP Ukagaka** → **✨ 創建新偽春菜** に移動

#### 必須フィールド

| フィールド | 説明 | 例 |
| --- | --- | --- |
| 名前 | 伺かの名前 | `フリーレン` |
| 画像 | 伺か画像の完全 URL | `https://example.com/ukagaka.png` |
| ダイアログ | ダイアログ内容、1 行に 1 つ | 下記の例を参照 |

```
私のサイトへようこそ！
今日はいい天気だね〜
最新の記事を見てみる？
魔法は時間をかけて研究するものだ。
```

#### オプションフィールド

| フィールド | 説明 |
| --- | --- |
| ダイアログファイル名 | 外部ダイアログファイルの名前（拡張子なし） |
| ダイアログファイルを生成 | チェックすると対応するダイアログファイルを自動生成 |

## カスタム表情システム

> 🎭 **v2.4.0 新機能**：各キャラクターが独自の表情セットを持てるようになりました。

表情システムは、ダイアログテキスト中のキーワードに基づき、キャラクター画像の横に対応する表情画像を自動表示します。**静的ダイアログと AI 生成ダイアログの両方で表情機能をサポートしています。**

### ファイル構造

キャラクターのフォルダ（`ghost/キャラクターID/`）に以下の構造を作成してください：

- `emojis/`：表情画像を保存（PNG、APNG、GIF をサポート）
- `キャラクターID-emoji.js`：表情制御スクリプト（`Frieren-emoji.js` をコピーして変更可能）
- `emoji-keywords.json`：表情トリガーキーワード設定（オプション、未作成の場合は内蔵の汎用マッピングを使用）

### キーワード設定（`emoji-keywords.json`）

```json
{
  "_meta": {
    "description": "キャラクター専用表情キーワード",
    "version": "1.0"
  },
  "mappings": {
    "happy": {
      "keywords": ["嬉しい", "happy", "lol"],
      "file": "happy.png",
      "weight": 10
    },
    "angry": {
      "keywords": ["怒り", "angry", "ぷんぷん"],
      "file": "angry.png",
      "weight": 10
    }
  }
}
```

| フィールド | 説明 |
| --- | --- |
| **keywords** | この表情をトリガーするキーワードリスト |
| **file** | `emojis/` フォルダ内の画像ファイル名 |
| **weight** | 重み（複数の表情がマッチした場合、重みが高いものが優先） |

## LLM 設定（AI 会話エンジン）

**設定** → **MP Ukagaka** → **LLM 設定** に移動

LLM（Large Language Model）機能により、AI を使用してダイアログを生成できます。4 つのプロバイダーをサポート：

| プロバイダー | 費用 | API Key |
| --- | --- | --- |
| **Ollama**（ローカル/リモート） | 完全無料 | 不要 |
| **Google Gemini** | 使用量に応じた課金 | 必要（[Google AI Studio](https://makersuite.google.com/app/apikey)） |
| **OpenAI** | 使用量に応じた課金 | 必要（[OpenAI Platform](https://platform.openai.com/api-keys)） |
| **Claude (Anthropic)** | 使用量に応じた課金 | 必要（[Anthropic Console](https://console.anthropic.com/)） |

![LLM 設定ページ](../screenshot4.PNG)

### クラウド AI（Gemini / OpenAI / Claude）

1. **LLM 設定** ページで対応するプロバイダーを選択
2. **API Key** フィールドに API Key を入力（API Key は自動的に暗号化して保存）
3. ドロップダウンからモデルを選択：
   - **Gemini**：Gemini 2.5 Flash（推奨、高速で低コスト）、Gemini 2.5 Pro
   - **OpenAI**：GPT-4.1 Mini（推奨、高速で低コスト）、GPT-4o Mini、GPT-4o
   - **Claude**：Claude Sonnet 4.6（推奨）、Claude Haiku 4.5（高速）、Claude Opus 4.7（進階）
4. 「接続テスト」ボタンをクリックして API Key が有効か確認

> 💡 **セキュリティ**：API Key は WordPress の暗号化機能で保存され、平文でデータベースに保存されることはありません。

> 🌍 **多言語サポート**：モデル選択ドロップダウンの説明文は、WordPress の言語設定に応じて繁体字中国語・英語・日本語で自動表示されます。

### Ollama（ローカル/リモート）

Ollama は完全無料のローカル AI で、API Key 不要です。

**事前準備：**

1. [Ollama 公式サイト](https://ollama.ai/) からダウンロードしてインストール
2. Ollama サービスを起動
3. モデルをダウンロード、例：ターミナルで `ollama pull qwen3:8b` を実行

**エンドポイントを設定：**

- **ローカル接続**：`http://localhost:11434`
- **リモート接続（Cloudflare Tunnel）**：`https://your-domain.com`

> 💡 プラグインは接続タイプ（ローカル/リモート）を自動検出し、タイムアウト設定を調整します。

**モデル名を設定：**

ダウンロード済みのモデル名を入力、例：

- `qwen3:8b`（推奨、速度と品質のバランスが良い）
- `qwen2.5:14b`（より高品質）
- `llama3.2`

> 💡 ターミナルで `ollama list` コマンドを使用してダウンロード済みモデルを確認できます。

「Ollama 接続テスト」ボタンをクリックして接続が正常か確認してください。

#### Modelfile でキャラクター専用モデルを作成（上級）

Ollama の Modelfile を使うと、キャラクター設定をモデルに直接埋め込むことができます。毎回 System Prompt を送信する必要がなくなり、**トークン消費を大幅に削減**し、応答の一貫性が向上します。

**サンプル Modelfile の使用：**

このプラグインはフリーレンキャラクターの Modelfile サンプルを提供しています：`example/frieren_modelfile.example.txt`

```powershell
# ステップ 1：サンプル Modelfile をコピー
Copy-Item wp-content\plugins\mp-ukagaka\example\frieren_modelfile.example.txt $HOME\frieren_modelfile
```

```powershell
# ステップ 2（オプション）：1 行目の FROM をダウンロード済みのモデルに変更
# FROM qwen3:8b
```

```powershell
# ステップ 3：重要！Modelfile を編集し、以下の変数を置き換え：
# {{admin_nickname}} → 管理人の完全なニックネーム
# {{admin_name}}     → 管理人の短い名前
# 置き換えないと、AI が会話中に {{admin_nickname}} をそのまま言ってしまう可能性あり
```

```powershell
# ステップ 4：モデルを作成
ollama create frieren -f $HOME\frieren_modelfile

# ステップ 5：テスト
ollama run frieren "こんにちは"
```

**LLM 設定** ページで、モデル名を `frieren`（または作成したモデル名）に設定します。

| 方法 | メリット | デメリット |
| --- | --- | --- |
| **Modelfile** | トークン消費なし、応答一貫性が高い | 変更時にモデル再構築が必要 |
| **バックエンド設定** | いつでも変更可能、柔軟 | 毎回トークン消費 |

> 💡 キャラクター設定が安定している場合は Modelfile を使用。まだ調整中の場合はバックエンド設定を使用することを推奨。

**よく使う Modelfile コマンド：**

```powershell
ollama list                                                           # 作成したモデルを一覧表示
ollama rm frieren                                                     # カスタムモデルを削除
ollama rm frieren; ollama create frieren -f $HOME\frieren_modelfile  # モデルを再構築
ollama show frieren                                                   # モデル情報を表示
```

### 詳細設定

#### LLM で内蔵ダイアログを置換

このオプションを有効にすると、すべての伺かダイアログが LLM によってリアルタイム生成され、静的ダイアログリストは使用されなくなります。

> 💡 この機能は「ページ感知」と同時に有効化できます。ページ感知条件に合う場合は AI が記事をコメント、それ以外はランダム生成されたダイアログを使用します。

#### 人格設定（System Prompt）

キャラクターの核心設定で、個性・話し方・行動ルールを定義します。

**サポート形式：**

- **プレーンテキスト形式**（基本）：直接テキスト説明を入力
- **Markdown 形式**（推奨）：見出し、リスト、強調などの構造化形式を使用
- **XML タグ形式**（上級）：より細かい制御を提供

**Markdown 形式例：**

```markdown
## キャラクター

あなたは魔法使いフリーレン。

## 性格

- 話し方は落ち着いていて、やや冷たい
- 魔法関連の話題に興味を示す
- 時間の感覚が人間と異なる

## 会話ルール

- 回答は50文字以内に
- 常体で話す（敬語は使わない）
```

**サポートされる変数（System Prompt で `{{変数名}}` を使用して動的置換）：**

| 変数 | 説明 |
| --- | --- |
| `{{ukagaka_display_name}}` | キャラクター名 |
| `{{language}}` | 応答言語（zh-TW、ja、en） |
| `{{time_context}}` | 時間コンテキスト（朝・昼・夜・深夜） |
| `{{admin_nickname}}` | 管理人の完全なニックネーム |
| `{{admin_name}}` | 管理人の短い名前 |
| `{{wp_version}}` | WordPress バージョン |
| `{{php_version}}` | PHP バージョン |
| `{{post_count}}` | 記事数 |
| `{{comment_count}}` | コメント数 |
| `{{days_operating}}` | 運営日数 |
| `{{theme_name}}` | テーマ名 |
| `{{theme_version}}` | テーマバージョン |
| `{{theme_author}}` | テーマ作者 |

> 💡 **長さの推奨**：クラウド AI（Gemini、OpenAI、Claude）は 500-1000 字以内を推奨（トークン節約のため）。ローカル LLM（Ollama）は 1000 字以上の詳細なプロンプトを使用でき、より良いキャラクター一貫性が得られます。

#### 思考モードを無効化（Qwen3、DeepSeek などのモデル）

有効にすると、Qwen3、DeepSeek などのモデルの思考行動を無効化し、応答効率が向上します。これらのモデルを使用する場合に推奨。

### Ollama リモート接続（Cloudflare Tunnel）

```bash
# Windows
cloudflared.exe service install <token>

# Linux/Mac
cloudflared service install <token>
```

トンネル URL を確認後、エンドポイントフィールドに `https://your-domain.com` を入力します。ngrok などその他のトンネルサービスもサポートしています。

## ページ感知機能

**設定** → **MP Ukagaka** → **AI 設定** に移動

ページ感知機能により、伺かは特定のページで記事内容に関連する AI コメントを自動生成できます。**LLM 設定ページで AI プロバイダーの設定を先に完了する必要があります。**

### 設定項目

#### 言語設定

AI 応答の言語を選択：繁体字中国語 / 日本語 / 英語

#### キャラクター設定（System Prompt）

ページ感知で使用するキャラクターの個性設定。形式と変数のサポートは [人格設定（System Prompt）](#人格設定system-prompt) と同じです。

#### ページ感知確率（%）

条件に合うページで AI コメントをトリガーする確率を設定（1-100%）。

| 推奨値 | 効果 |
| --- | --- |
| 10-30% | より自然で、頻繁すぎない |
| 50% | バランスの取れたトリガー頻度 |
| 80-100% | ほぼ毎回トリガー |

#### トリガーページ

どのページタイプで AI コメントをトリガーするかを設定。複数条件はカンマで区切ります：

| タグ | 説明 |
| --- | --- |
| `is_single` | 単一記事 |
| `is_page` | 固定ページ |
| `is_home` | ホームページ |
| `is_front_page` | 静的フロントページ |
| `is_archive` | すべてのアーカイブページ |
| `is_category` | カテゴリページ |
| `is_tag` | タグページ |

例：`is_single,is_page`

#### AI 会話の表示時間（秒）

AI が生成したコメントがどれくらい表示されてから自動的に消えるかを設定。

| 推奨値 | 用途 |
| --- | --- |
| 5-10 秒 | 短いコメント、読書を邪魔しない |
| 10-15 秒 | バランスの取れた表示時間 |
| 15-20 秒 | 長いコメント |

#### 初回訪問者への挨拶を有効化

有効にすると、サイトを初めて訪問した訪問者に特別な挨拶メッセージが表示されます。

#### 初回訪問者挨拶プロンプト

初回訪問者への挨拶プロンプトを設定。キャラクター設定と組み合わせてパーソナライズされた挨拶を生成します。System Prompt と同じ `{{変数名}}` 置換をサポートしています。

例：

```
初めて訪問した訪問者に挨拶し、このサイトを簡単に紹介してください。
```

#### ボット検出（Bot Detection）

システムはクローラーボットを自動的に検出します。ボットの訪問を検出した場合、特定の会話反応（「侵入者発見」など）をトリガーできます。

![Bot 会話の例](../screenshot5.PNG)

### ページ感知機能のワークフロー

1. 訪問者が「トリガーページ」条件に合うページにアクセス
2. 「ページ感知確率」に基づいてトリガーするか決定
3. トリガー時：記事内容を読み込む → キャラクター設定と組み合わせる → AI サービスを呼び出してコメント生成 → 吹き出しに表示 → 「AI 会話の表示時間」後に自動消去

### LLM 設定との関係

- **LLM 設定ページ**：どの AI サービスを使うか（プロバイダー、API Key、モデル）を制御
- **AI 設定ページ（ページ感知）**：いつトリガーするか、どのように表示するかを制御

両方を同時に有効化することも可能です：ページ感知条件に合う場合は AI が記事をコメント、それ以外の場合は LLM がランダムなダイアログを生成します。

## インタラクティブチャットモード

> 🎉 **v2.3.0 新機能**：訪問者が伺かキャラクターと直接リアルタイムで多ターン会話できるようになりました！

### インタラクティブチャットモードとは？

インタラクティブチャットモードは、フロントエンドの「伺か変更」ボタンをリアルタイムチャットインターフェースに変換し、訪問者がキャラクターと実際の多ターン会話を行えるようにします。ページ感知機能（記事への自動コメント）とは異なり、チャットモードは訪問者が完全に主導でトリガーします。

**LLM 設定で AI プロバイダーを設定してから有効化してください。**

### 有効化方法

1. **設定 → MP Ukagaka → ⚙️ 通用設定** に移動
2. 「💬 対話設定」セクションで「**インタラクティブチャット機能を有効化**」にチェック
3. 「保存」ボタンをクリック
4. サイトのフロントエンドで「伺か変更」ボタンが「💬 対話」ボタンに変わります

### 使用方法

1. 画面右下の「💬 対話」ボタンをクリック
2. チャットボックスが展開され、ウェルカムメッセージが表示
3. 下部の入力ボックスにメッセージを入力、Enter キーを押すか送信アイコンをクリック
4. AI が入力に基づいて応答を生成
5. 会話を続けることができ、システムは以前の内容を記憶

会話履歴は現在のページにのみ保持されます（ページ更新後にクリア）。

![インタラクティブチャットモードデモ](../screenshot3.PNG)

### スラッシュコマンド

| コマンド | 対象 | 説明 |
| --- | --- | --- |
| `/help` | 全員 | 利用可能なコマンド一覧を表示 |
| `/reset` | 管理者のみ | 現在の会話履歴を消去 |
| `/clear` | 管理者のみ | `/reset` と同じ |
| `/remember` | 管理者のみ | 最近の会話から事実を抽出し、キャラクターの記憶として保存 |
| `/debug_mcp` | 管理者のみ | MCP/アビリティ診断レポートを表示 |

> 管理者専用コマンドは WordPress のログイン状態によって判定されます。非ログインユーザーがこれらのコマンドを入力すると、キャラクターがキャラクターらしく拒否します。

### チャットモード vs ページ感知

| 機能 | インタラクティブチャットモード | ページ感知モード |
| --- | --- | --- |
| **トリガー方法** | 訪問者が「対話」ボタンを主体的にクリック | 自動トリガー（確率ベース） |
| **インタラクティブ性** | 双方向多ターン対話 | 一方向コメント |
| **コンテキスト** | 完全な会話履歴を維持 | 現在のページ内容のみ分析 |
| **トークン消費** | 会話ターンごとに累積 | 単一コメント |
| **有効化場所** | `⚙️ 通用設定` → 対話設定 | `🧠 AI 設定` → ページ感知 |

### アビリティ（Abilities）

> 🛠️ **v2.8.0 新機能**：キャラクターがサイト管理タスクを実行できるようになりました。

アビリティとは、キャラクターが会話中に自動的に呼び出せるサーバーサイドの機能です。管理者がチャットモードで自然な言葉でリクエストするだけで、キャラクターがバックエンドのツールを実行し、結果を返します。特別なコマンドは不要です — 普通に話しかけるだけで OK です。

> ⚠️ 管理系アビリティ（IP Ban、データ消去など）は WordPress 管理者としてログインしている場合のみ使用できます。一般訪問者がこれらの操作をリクエストしても、キャラクターが拒否します。

## 思考モード

> 🧠 **v2.3.0 新機能**：Ollama モデルが回答前に思考することで、応答品質が向上します。

### 思考モードとは？

思考モードは、対応する AI モデル（Qwen3、DeepSeek など）が回答前に内部推論を行えるようにします。思考プロセスは訪問者には表示されず、最終応答のみを表示します。

> 💡 Gemini、OpenAI、Claude などのクラウドサービスはこの設定が不要です。思考プロセスはサービス側で内部処理されています。

### デフォルト動作（v2.3.0 以降）

思考モードは**デフォルトで有効**（`think = true`）です。AI がまず考えてから回答し、出力品質を確保します。

**サポートされる Ollama モデル：**

- **Qwen3** シリーズ：`qwen3:8b`、`qwen3:14b` など
- **DeepSeek** シリーズ：`deepseek`、`deepseek-r1` など

### 無効化する方法

より速い応答が必要な場合（一部精度を犠牲に）：

1. **設定 → MP Ukagaka → LLM 設定** に移動
2. 「Ollama 設定」セクションで「**思考モードを無効化（Qwen3、DeepSeek などのモデル）**」にチェック
3. 「保存」ボタンをクリック

| 特性 | 思考モード（デフォルト） | 非思考モード |
| --- | --- | --- |
| **応答品質** | 高精度 | 速いが精度が低い可能性 |
| **応答速度** | やや遅い（+1-2 秒） | 速い |
| **Context Window（チャットモード）** | 8192 トークン | 4096 トークン |
| **思考と応答** | 完全分離 | 混在する可能性 |

## 天気感知機能

> 🌤️ **v2.5.0 新機能**：伺かも天気を感じられるようになりました！

[Open-Meteo](https://open-meteo.com/) の無料 API を使用し、**API Key の申請は不要**です。有効にすると、キャラクターは現地の天気状況を把握し、ダイアログや AI コメントの中で言及できるようになります（天気変数をサポートする System Prompt と組み合わせる必要があります）。

### 設定手順

1. **LLM 設定** ページで「**天気感知機能を有効化**」にチェック
2. 所在地の緯度と経度を入力（デフォルト：台北 — 25.0330, 121.5654）
   - [Google Maps](https://www.google.com/maps) で地図を右クリックすると座標をコピーできます
3. 「天気 API をテスト」ボタンをクリックして天気データを取得できるか確認

### 機能

- 現在の気温と天気状況（晴れ、雨、曇りなど）をリアルタイム取得
- 明日の天気予報
- 今日・明日の降水確率
- 自動キャッシュで頻繁なリクエストを回避

## 自動日記機能

> 📓 **v2.5.0 新機能**：キャラクターが自動で日記を書くようになりました！

**設定** → **MP Ukagaka** → **日記設定** に移動

### 自動日記機能とは？

有効にすると、キャラクターは設定された非常に低い確率で自動的に日記記事を作成して投稿します。日記には以下が含まれます：

- 今日の日付と季節
- 現在の天気状況（天気機能が有効な場合）
- キャラクター設定に合った気分や考え
- ランダムな日常の出来事

### 基本設定

| 設定項目 | 説明 |
| --- | --- |
| 自動日記機能を有効化 | オンにすると、システムは毎日1回、日記生成をトリガーするかどうかをチェック |
| 投稿カテゴリ | 日記記事を投稿するカテゴリを選択 |
| 投稿者 | どの WordPress ユーザーとして日記を投稿するかを選択 |
| トリガー確率 | 日記をトリガーする毎日の確率（1%-10%） |
| 記事の署名 | 各日記の末尾に追加する署名テキスト（空欄の場合は追加なし） |

**トリガー確率の目安：**

| 確率 | 月あたりの投稿数目安 |
| --- | --- |
| 2% | 0~1 記事（レア） |
| 5% | 1~2 記事（たまに） |
| 10% | 3 記事（頻繁） |

> ⚠️ 日記で埋め尽くされないよう、2-5% 程度に保つことをお勧めします。

> 💡 先に WordPress の投稿カテゴリで専用カテゴリ（例：「フリーレン手記」）を作成してから選択することをお勧めします。

### 日記 AI プロバイダー

日記機能は**独立した AI 設定**を使用します。例えば、会話機能には Ollama（無料）を使用し、日記機能には Gemini 2.5 Flash（高品質で安価）を使用することができます。

LLM 設定と同じプロバイダーをサポート：Gemini、OpenAI、Claude、Ollama。

### 日記テーマ設定（diary.json）

日記の「何を書くか」はキャラクターフォルダ内の `diary.json` で制御されます。このファイルは日記のテーマカテゴリ、プロンプト、出現確率（weight）を定義します。

**ファイル位置：** `ghost/キャラクターID/diary.json`

詳細な形式については [人格作成ガイド](GHOST_CREATE_GUIDE.md) を参照してください。

### テスト機能

設定ページの下部にある「**今すぐ日記を生成（テスト）**」ボタンをクリックすると、システムはすぐに日記の生成と投稿を試みます。AI 接続、投稿設定、内容スタイルが期待通りかを確認するのに使用できます。

## 外部ダイアログファイル

伺かは外部ファイルからダイアログを読み込めます。TXT と JSON の 2 種類の形式をサポートしています。

**ファイル場所：** `wp-content/plugins/mp-ukagaka/dialogs/キャラクター名.json`

```json
{
  "messages": ["最初のダイアログ", "2番目のダイアログ", "3番目のダイアログ"]
}
```

# よくある質問

### 伺かが表示されない

1. 「デフォルトで伺かを表示」にチェックが入っているか確認
2. 現在のページが除外リストに入っていないか確認
3. ブラウザキャッシュをクリア
4. F12 でコンソールを表示し、JavaScript エラーがないか確認

### AI がトリガーされない

1. 「ページ感知機能」が有効になっているか確認
2. API Key が正しいか確認
3. 現在のページがトリガー条件に合っているか確認
4. 「ページ感知確率」を一時的に 100% に設定してテスト
5. 記事内容が 500 文字を超えているか確認

### ダイアログが正しく表示されない

1. ダイアログファイル形式が正しいか確認
2. TXT 形式：各ダイアログは**空行**で区切る
3. JSON 形式：有効な JSON であることを確認

### AI 応答が遅い

1. より高速なモデルに切り替えてみる（例：`gemini-2.5-flash`、`qwen3:8b`）
2. **クラウド AI**：System Prompt を短くすると API 処理時間が短縮
3. **ローカル LLM（Ollama）**：Prompt の長さは応答速度にあまり影響しない、モデルサイズやハードウェアの調整を優先
4. ネットワーク接続を確認

### LLM 接続に失敗

**Ollama：**

1. Ollama サービスが実行中か確認
2. ポートが 11434 か確認、ブラウザで `http://localhost:11434` にアクセスしてみる
3. リモート接続：Cloudflare Tunnel サービスが実行中か、トンネル URL が正しいか確認

**Gemini / OpenAI / Claude：**

1. API Key が正しく、期限切れでないか確認
2. API Key に十分な残高があるか確認
3. ネットワーク接続が正常か確認、ファイアウォールが API リクエストをブロックしていないか確認

### AI コストを制御するには

1. 「ページ感知確率」を下げる（推奨 10-20%）
2. 「トリガーページ」を制限（`is_single` のみでトリガー）
3. より安価なモデルを使用（例：`gemini-2.5-flash`、`gpt-4o-mini`）
4. Ollama を使用（ローカル実行、完全無料）
